# Report Spec - Cookie Cats A/B test (Power BI)

## Report identity
- Report name: CookieCats (powerbi/CookieCats.pbip)
- Semantic model: CookieCats.SemanticModel (local, new; Import from CSV tables written by the Python pipeline)
- Audience: hiring managers / analytics leads reviewing a DA portfolio; secondarily a game product manager deciding the gate position
- Primary purpose: give a ship / don't-ship decision on the gate position, then show the evidence, the engagement and power context, and the data-quality caveats behind it
- Delivery target: local PBIP only, committed to the repo, with page screenshots in the README (no Fabric publish)

## Semantic model binding
- Entry mode: Local Model (created in this build; the repo has no model yet)
- Model name: CookieCats
- connectionString: byPath ../CookieCats.SemanticModel
- Data source: M parameter `CsvFolder` = `D:\Vi\DA_Game\cookie-cats-ab-test\powerbi\data\`

## User decisions and constraints
- Scope: the findings already published in README.md / results/metrics.json; no new analysis
- Page count: 4
- Interactivity: page navigator top right on every page; one slicer (arm) on the Engagement page only; "Show as table" left available
- Design direction: same editorial identity as the Flood-It report so the three portfolio reports read as one body of work
- Publishing: none
- Tooling: Python exports CSVs; TMDL model written directly; PBIR generated by a Node script (same pattern as Flood-It `build_report.js`); powerbi-report-author CLI validate; Power BI Desktop preview + screenshots
- Model edit permissions: new model; every number on a page comes from a measure or a column; no hard-coded numbers in DAX
- Accessibility: WCAG AA contrast on #FCFCFB, alt text on every chart, arm identity never colour-only (legend + axis labels)
- Data caveats: no timestamps; SRM p = 0.009; one outlier player (49,854 rounds); retention is a single-day flag; no revenue column

## Narrative
- Core story: moving the gate from level 30 to 40 lowers day-7 retention by 0.82 pp; three statistical views agree; engagement is flat, so the loss is about coming back, not playing less; the test had just enough power; the uneven split must be explained before the size is final.
- Audience promise: every page opens with a one-line takeaway; every chart has its definition as subtitle and an insight with a source line underneath.
- Key questions answered: What should we ship? How sure are we? Did engagement change? Was the test big enough? Can we trust the experiment?

## Design identity
- Tone: Editorial analyst briefing (same as Flood-It) - warm off-white page, near-black text, one accent per arm, generous whitespace
- Signature: takeaway headline (left, 28pt semibold) + definition subtitle on every chart + insight card with a coloured left accent bar ending in a grey `Source:` line

## Page plan
1. Decision - Executive Summary (variant A: KPI strip + chart + decision panel). Six KPI cards; D1/D7 retention by arm (clustered columns); recommendation panel.
2. Evidence - Analytical Canvas (variant C: table on top, paired charts below). Statistical test table (two rows: D1, D7); D7 and D1 bootstrap histograms; one insight band.
3. Engagement and power - Comparative Benchmark (variant A: halves). Rounds survival lines by arm (arm slicer); power curve with the observed effect as a constant line; two insight cards.
4. Data checks and limitations - Narrative Story (variant A: two columns). Data check table; limitations text.

## Design system summary
- Theme: `PortfolioEditorial` (copy of Flood-It `FloodItEditorial`) - background #FCFCFB, text #0B0B0B, secondary #52514E, dataColors [#2A78D6, #EB6834, #1BAF7A], Segoe UI
- Colour semantics: blue #2A78D6 = gate 30 (control) everywhere; orange #EB6834 = gate 40 (test) everywhere; bootstrap bars orange (they are test minus control); power curve blue, observed effect orange
- Typography: Segoe UI Semibold 28 (page headline), Semibold 14 (visual title), 11 (subtitle/definition), 12 (insight), 10 grey (source)
- Layout: 1920 x 1080, 12 x 12 grid, margin 32, gutter 24, snap 8; header row reserved
- Accessibility: AA contrast; alt text = chart title + insight; tooltips on every chart

## Model requirements
- Tables (CSV in powerbi/data, written by a new `python -m cookie_cats.powerbi_export` step from the same pipeline objects as metrics.json):
  - `fact_players` - 90,189 rows: userid, version, arm_label ("Gate 30 (control)" / "Gate 40 (test)"), arm_order, sum_gamerounds, retention_1 (0/1), retention_7 (0/1), is_rounds_outlier (0/1)
  - `fact_tests` - 2 rows (metric): metric_label, p_control, p_treatment, diff_pp, ci_low_pp, ci_high_pp, rel_change, p_value, p_holm, boot_share_treatment_worse, bayes_prob_control_better, mde_pp_80power
  - `fact_bootstrap_hist` - metric x 60 bins: metric, bin_center_pp, resamples, in_ci (0/1)
  - `fact_rounds_survival` - arm x rounds 0..200: arm_label, arm_order, rounds, share_at_least
  - `fact_power_curve` - 400 rows: players_per_arm, mde_pp
  - `fact_checks` - one row per check: check_order, check, value_text, verdict
  - `kpi_metrics` - key/value pairs for scalars (srm_p, srm_chi2, players_lost_per_100k + CI, observed D7 effect, rounds outlier max)
- Measures (`_Measures`): Players; D1 Retention; D7 Retention (DIVIDE of SUM over COUNTROWS, live from fact_players); D7 Retention Gate 30; D7 Retention Gate 40; D7 Difference pp; D7 CI Low pp; D7 CI High pp; D7 Holm p; D7 Players Lost per 100k; SRM p; Observed D7 Effect pp; Bootstrap Resamples; Share At Least; MDE pp
- Relationships: none needed (each visual reads one table)
- Sort: arm_label by arm_order
- Reconciliation: a DAX query checks every measure against results/metrics.json (tolerance 1e-6), as in Flood-It
